# TCWGlobal Slack Bot — 설계 & 운영 계획서

> **레포**: `tcwglobal-slack-bot`
> **앱 이름**: TCWGlobal
> **1차 범위**: International PTO 요청 폼 자동 제출
> **확장 예정**: Expense 요청 폼

---

## 1. 무엇을 만드는가

Slack 사이드바에서 **TCWGlobal** 앱을 열면 저장된 내 정보와 폼 버튼이 보입니다. 버튼을 누르면 모달이 뜨고, 요청별 정보만 입력해 제출하면 봇이 Formstack 폼을 대신 채워 보냅니다.

```
┌──────────────────────────────────────────┐
│  TCWGlobal                               │
├──────────────────────────────────────────┤
│  Your information                        │
│  Hong Gildong · gildong@example.com       │
│  Acme Corp · South Korea                  │
│  Manager: Jane Doe (jane@acme.com)        │
│                                          │
│  [ New PTO request ]  [ Edit info ]       │
│                                          │
│  ← Expense 추가 시 여기 버튼이 하나 더 생김  │
└──────────────────────────────────────────┘
```

**이름·이메일·사번·소속·매니저는 한 번만 입력**하고, `Edit info`를 누르기 전까지 계속 재사용됩니다. 매번 입력하는 건 날짜와 휴가 유형뿐입니다.

## 2. 핵심 설계 결정

### 2-1. 브라우저를 띄우지 않습니다

대상 폼은 로그인·reCAPTCHA 없는 평범한 HTML 폼입니다. 브라우저가 하는 일은 결국 HTTP POST 하나를 보내는 것이고, 그 요청 형식은 HTML에 그대로 공개돼 있습니다. 그래서 `fetch`로 직접 보냅니다.

| | Playwright 방식 | 채택한 방식 |
|---|---|---|
| 제출 시간 | 5–20초 | **~300ms** |
| 컨테이너 | 1.5GB | **150MB** |
| 메모리 | 500MB+ | **50MB** |

**파생 효과가 큽니다.** 제출이 300ms면 Slack의 3초 응답 제한 안에서 동기 처리가 가능해지고, 그러면 큐·Redis·워커 프로세스가 전부 불필요해집니다. 인프라의 대부분이 이 결정 하나에서 사라졌습니다.

부가적으로, 동기 처리라 제출이 거부되면 **모달이 안 닫혀서 입력값이 그대로 남습니다.** 비동기 큐를 썼다면 모달이 닫힌 뒤 실패 알림이 오고, 사용자는 처음부터 다시 입력해야 합니다.

### 2-2. DB 대신 암호화된 JSON 파일

저장할 것은 사용자당 프로필 하나이고, 쿼리할 게 없습니다. "이 Slack 사용자의 정보"를 꺼내는 게 전부고 전체 데이터가 수십 KB입니다.

```
data/profiles.json
{
  "U01ABCDEF": { "ciphertext": "k9Xv2mQp7...", "iv": "...", "authTag": "..." },
  "U02GHIJKL": { "ciphertext": "mR4nB8kL2...", "iv": "...", "authTag": "..." }
}
```

프로세스 메모리의 객체가 곧 캐시라 별도 캐시 계층도 없습니다. 읽기는 전부 메모리, 쓰기(= `Edit info` 저장)만 디스크로 갑니다.

**"변경 버튼 누르기 전까지 유지"가 구조적으로 보장됩니다** — 값을 바꾸는 코드 경로가 `saveProfile` 하나뿐이라, 다른 방법으로 값이 바뀔 수가 없습니다.

사용자 50명이 넘어가면 매번 전체 파일을 다시 쓰는 비용이 보이기 시작합니다. 그때 `store/profiles.ts`만 SQLite 버전으로 교체하면 되고, 인터페이스가 같아서 다른 파일은 안 건드립니다.

### 2-3. 슬래시 커맨드 대신 App Home

`/pto` 같은 커맨드는 **존재를 알아야 쓸 수 있습니다.** App Home은 사이드바에서 앱을 클릭하면 바로 뭘 하는 앱인지 보이고, 저장된 정보도 항상 눈에 띕니다.

부수적으로 `commands` 스코프가 빠져서 앱 권한이 더 줄어듭니다.

### 2-4. 폼을 등록 가능한 구조로 (확장 대비)

Expense를 나중에 붙일 것이므로, **폼별로 다른 것과 공통인 것을 지금 분리**합니다.

```
공통 (한 번 만들면 끝)          폼별 (폼마다 하나씩)
─────────────────────          ──────────────────
formstack/engine.ts            forms/pto/schema.json
store/profiles.ts              forms/pto/index.ts
slack/home.ts                  forms/pto/modal.ts
slack/handlers.ts              
slack/messages.ts              forms/expense/...  ← 나중에 추가
```

핵심은 **Profile이 폼과 무관하게 정의된다**는 점입니다. PTO 폼과 Expense 폼은 같은 사람의 이름을 서로 다른 Formstack 필드 ID로 받겠지만, 그 매핑은 각 폼의 `schema.json`에 있습니다. 사용자는 정보를 한 번만 입력하고 두 폼 모두에서 재사용합니다.

Expense 추가 시 바뀌는 것: **디렉터리 하나 + 레지스트리 한 줄.** 엔진·저장소·홈·핸들러는 손대지 않습니다. (`IMPLEMENTATION.md` §12에 이 조건을 검증 기준으로 명시해뒀습니다)

과하게 추상화하지는 않았습니다. 폼 빌더나 플러그인 시스템이 아니라, 인터페이스 하나와 배열 하나입니다.

## 3. 시작 전 필수 작업 — 폼 조사

**이 프로젝트에서 유일하게 사람만 할 수 있는 작업입니다.** 나머지는 전부 코드로 처리되지만, "어떤 필드가 무슨 의미인지"는 눈으로 봐야 합니다.

브라우저에서 폼을 열고 **F12 → Network** 탭을 켠 뒤, 본인 이름 + **과거 날짜 하루짜리**로 한 번 제출합니다. (담당자에게 취소 요청하면 됩니다)

제출 후 POST 요청에서 네 가지를 기록합니다.

| 확인할 것 | 어디서 | 왜 중요한가 |
|---|---|---|
| **필드명** | Payload 탭 | `field12345678` 형태. 라벨과 매칭 |
| **날짜 포맷** | Payload의 날짜값 | `08/17/2026` vs `17/08/2026`. **가장 사고 나기 쉬운 곳** |
| **select/radio 값** | Payload의 leave type | `Vacation`인지 `1`인지. 화면 라벨과 다른 경우 많음 |
| **성공 문구** | 제출 후 화면 | 성공 판정의 **유일한** 기준 |

요청에 **우클릭 → Copy as cURL** 하면 위 내용이 한 덩어리로 나옵니다.

날짜 필드가 `field123-M` / `-D` / `-Y` 셋으로 쪼개져 있는지도 확인하세요. Formstack이 종종 그렇게 합니다.

이 결과를 `src/forms/pto/schema.json`에 옮기면 구현이 시작됩니다.

## 4. 진행 순서

```
[✅] Slack 앱 생성 (TCWGlobal)
[✅] Bot Token (xoxb-) / App Token (xapp-)
[✅] 로컬 연결 확인
[  ] 앱 아이콘 준비 (아래 참고)
[  ] ← 폼 조사 (F12 → Network → 제출 → Payload)
[  ] schema.json 작성
[  ] 구현 (IMPLEMENTATION.md §13 build order)
[  ] 로컬에서 실제 제출 성공 + 담당자 수신 확인
[  ] Railway 배포
[  ] 팀에 안내
[  ] (나중에) Expense 폼 추가
```

### 앱 아이콘

공식 홈페이지의 TCWGlobal 로고를 쓰되, 그대로는 업로드가 안 됩니다. Slack은 **512×512 이상 정사각형 PNG**를 요구하는데 원본은 400×199 WebP입니다.

세 가지를 손봐야 합니다.

1. **해상도** — HubSpot CDN URL의 `width` 파라미터를 키워서 재요청. 확대해 뭉개지면 마케팅팀에 SVG 원본 요청
2. **마크만 사용** — 사이드바에서 아이콘은 **20px 정도로 렌더링**됩니다. 가로형 lockup을 정사각형에 넣으면 워드마크가 안 읽힙니다. 마스코트 부분만 크롭하세요. 앱 이름은 아이콘 옆에 텍스트로 나오니 아이콘 안에 글자를 반복할 필요가 없습니다
3. **배경** — 흰색보다 브랜드 컬러 단색이 낫습니다. 로고에 흰색 요소가 있으면 다크 모드에서 사라집니다

업로드는 매니페스트가 아니라 **Basic Information → Display Information → App icon**에서 직접 합니다. 변환 명령과 세부는 `IMPLEMENTATION.md` §11에 있습니다.

업로드 후 실제 사이드바 크기에서 라이트/다크 모드 둘 다 확인하세요. 시안에서 예뻐도 20px에서 뭉개지는 경우가 많습니다.

**Railway 배포는 마지막입니다.** Socket Mode는 로컬에서도 실제 Slack이 그대로 붙기 때문에, 개발 중에는 배포할 이유가 없습니다. 코드 수정 반영이 즉시 되고 로그도 터미널에서 바로 보입니다.

배포는 "완성된 것을 24시간 돌리는" 단계이고, 다른 사람도 쓰기 시작할 때 필요해집니다.

## 5. 배포

### 5-1. 왜 상시 실행이 필요한가

Socket Mode는 Slack과 WebSocket 연결을 **계속 붙들고 있는** 방식입니다. 사용자가 언제 버튼을 누를지 모르니 받아줄 프로세스가 살아 있어야 합니다. 터미널을 닫으면 봇도 멈춥니다.

이 제약 때문에 서버리스 플랫폼이 전부 탈락합니다.

| 플랫폼 | 상시 실행 | 파일 저장 | 비용/월 | 판정 |
|---|---|---|---|---|
| **Railway** | ✅ | ✅ Volume | $5 | ⭐ 설정이 가장 쉬움 |
| **Fly.io** | ✅ | ✅ Volume | ~$2 | ⭐ 저렴, 도쿄 리전 |
| Render | ✅ | ✅ Disk | $7 | 무난 |
| 사무실 상시 PC / 라즈베리파이 | ✅ | ✅ | ~$0 | `docker run` 한 줄 |
| Oracle Cloud Free Tier | ✅ | ✅ | $0 | ARM 무료 |
| Vercel / Cloudflare Workers | ❌ | ❌ | — | 구조 변경 필요 |

**Vercel을 쓰려면** HTTP 모드 전환 + 외부 KV 도입 + 전체 async 변경이 필요하고, 콜드 스타트 1~2초가 Slack의 3초 제한과 `trigger_id` 만료에 걸려 간헐적 실패가 납니다. 권하지 않습니다.

인바운드 연결이 필요 없어서 **자체 호스팅 문턱이 매우 낮습니다.** 공인 IP·포트포워딩·도메인·인증서가 전부 불필요합니다. 상시 켜져 있는 기계가 이미 있다면 그게 가장 간단합니다.

### 5-2. Railway 절차

```
1. GitHub에 tcwglobal-slack-bot push
2. railway.app → New Project → Deploy from GitHub repo
3. Settings → Volumes → Add Volume, Mount path: /data
4. Variables 탭에 환경변수 입력
5. Settings → Health Check → 비워둘 것
```

**함정 세 가지**

| 함정 | 증상 | 대응 |
|---|---|---|
| Health check 설정 | 재시작 루프 | HTTP 포트를 안 여는 앱이라 항상 실패. 반드시 비워둘 것 |
| 볼륨 경로 불일치 | 재배포마다 프로필 소실 | Mount path와 `DATA_FILE`이 같은지 확인 |
| Public Domain 생성 | 불필요한 노출 | Socket Mode라 도메인이 필요 없음 |

**배포 직후 반드시 검증**: 정보 등록 → 아무거나 커밋해서 재배포 → App Home에 정보가 그대로 있는지 확인. 여기서 사라지면 볼륨 설정이 잘못된 겁니다. 이건 로컬에서 재현이 안 돼서 나중에 원인 찾기가 성가십니다.

변수 목록과 로컬/Railway 차이는 `IMPLEMENTATION.md` §10에 있습니다.

### 5-3. 키 관리

`PROFILE_ENC_KEY`만 성격이 다릅니다.

| 시크릿 | 유출 시 | 분실 시 |
|---|---|---|
| `SLACK_BOT_TOKEN` | Reinstall to Workspace | 재발급 |
| `SLACK_APP_TOKEN` | Revoke → Generate | 재발급 |
| `PROFILE_ENC_KEY` | 교체 후 전원 재등록 | **복구 불가** |

Slack 토큰 둘은 언제든 재발급하면 되지만, 암호화 키를 잃으면 저장된 프로필을 아무도 복구할 수 없습니다. **첫 배포 전에 비밀번호 관리자에 백업**하세요. 그리고 로컬과 Railway에서 같은 값을 써야 합니다.

## 6. 에러 처리 방침

폼 필드가 바뀌거나 다른 문제가 생기면 **봇이 DM으로 알려주고, 수동 제출할 수 있게 값을 넘겨줍니다.**

### 6-1. 어디에 보여줄지

| 에러 | 위치 | 이유 |
|---|---|---|
| 사용자가 고칠 수 있음 (종료일 < 시작일) | 모달 인라인 | 모달이 안 닫혀 값 그대로 수정 가능 |
| 봇이 고쳐야 함 (필드 변경, 네트워크) | 모달 닫고 **DM** | 링크·복붙용 값을 담을 수 있음 |

모달 인라인 에러는 평문만 지원해서 버튼·링크가 안 들어갑니다.

### 6-2. 실패 DM에 반드시 들어갈 것

"Submission failed"만 보내면 사용자가 할 수 있는 게 없습니다.

```
❌ Could not submit your PTO request

Reason · The form structure has changed
Fields not found on the form: field12345691

[ Open the form ]

Copy these values and submit manually:
Full name      Hong Gildong
Email          gildong@example.com
...
Leave type     Vacation
Dates          2026-08-17 ~ 2026-08-21
Total days     5

Fix · Re-run the extract-schema script and update schema.json
```

**복붙용 값 블록이 핵심입니다.** 봇이 죽어도 사용자가 30초 안에 수동 제출을 마칠 수 있습니다.

### 6-3. cron 감시를 두지 않는 이유

별도 워크플로로 매일 폼을 감시하는 대신, **제출 직전에 필수 필드 존재 여부를 확인**합니다. 어차피 hidden 필드 수집 때문에 폼 페이지를 GET하므로 추가 비용이 0입니다.

폼이 바뀐 사실을 다음 제출 시점에야 알게 되지만, 그 사이에 제출이 없었다는 뜻이라 실질 손해가 없습니다.

## 7. 팀 공개 방침

Slack 앱 설치 자체로는 **누구에게도 알림이 가지 않습니다.** 이 봇은 채널에 들어갈 이유가 없고(App Home + DM만 사용), 스코프에 채널 권한이 없어 아무 채널에나 글을 쓸 수도 없습니다.

`#general`에 "added an integration" 시스템 메시지가 뜰 수는 있는데, 이건 Slack이 워크스페이스 변경사항을 기록하는 것이지 봇이 그 채널에 연동되는 게 아닙니다. 워크스페이스 설정에 따라 이미 꺼져 있는 경우도 많습니다.

**권하는 순서**

1. 조용히 설치
2. **본인이 며칠 먼저 사용**하며 필드 매핑·날짜 포맷 검증
3. 안정되면 팀 채널에 사람이 직접 안내

2번을 건너뛰지 마세요. 날짜 포맷이 잘못된 상태로 공지하면 여러 명의 휴가 신청이 잘못 들어갑니다.

### 명시적 트레이드오프

- **단일 프로세스 + 인메모리 캐시**: 인스턴스를 2개 이상 띄우면 상태가 어긋납니다. 이 규모에서는 1개로 고정하세요.
- **큐 없음**: 제출 실패 시 사용자가 다시 눌러야 합니다. 대신 모달에 값이 남아 재시도가 3초면 끝나므로 이 규모에서는 큐보다 나은 UX입니다.
- **hidden 필드 매번 수집**: 요청당 150ms를 더 쓰는 대신 토큰 만료·honeypot 관련 버그를 통째로 없앴습니다.
- **폼 레지스트리**: 폼이 끝까지 하나뿐이었다면 불필요한 간접층입니다. Expense가 확정된 상황이므로 지금 넣는 게 맞지만, 세 번째 폼이 나오기 전까지는 이 이상 추상화하지 않습니다.
